You are acting as a software architect and AI system designer.

Design the foundational architecture for the following capstone project.

Project Title:
Environment-Adaptive Pollution Monitoring and Visual Sensorization System Using Existing CCTV Infrastructure

Target Edge Device:
- Raspberry Pi 4 Model B
- RAM: 4GB
- OS: Raspberry Pi OS 64-bit Lite
- No desktop GUI should be assumed
- The system should run as a lightweight headless edge service

Core Objective:
Transform already-installed fixed CCTV cameras from simple recording devices into environment-aware monitoring systems capable of analyzing pollution states such as littering, cigarette butt accumulation, and environmental degradation.

This is NOT simply “YOLO object detection on CCTV.”
The core concept is:
- reusing existing CCTV infrastructure
- learning location-specific normal states
- detecting persistent pollution-related changes
- quantifying pollution levels over time
- extracting local environmental data visually using OCR

System Assumptions:
- CCTV cameras are fixed-view cameras
- CCTV video is accessed through RTSP or similar stream
- Training is performed on a server
- Inference is performed on Raspberry Pi 4B 4GB
- Raspberry Pi uses Raspberry Pi OS 64-bit Lite
- The edge device should be resource-conscious
- The system should support future acceleration options such as Coral USB Accelerator

Main System Flow:
1. Existing CCTV provides video stream
2. Server collects 1–2 months of location-specific video data
3. Server trains or fine-tunes a location-specific model
4. Optimized model is deployed to Raspberry Pi
5. Raspberry Pi performs lightweight inference locally
6. Detected pollution data is sent to the central server
7. Dashboard visualizes pollution level, events, charts, and reports

Core Features:

A. Pollution Object Detection
- Detect cigarette butts, litter, trash, and waste objects
- Prefer lightweight models suitable for Raspberry Pi 4B
- Consider YOLOv8n, YOLOv5n, MobileNet-SSD, TFLite models, or ONNX Runtime
- SAHI may be considered only as an optional optimization for small objects, not a mandatory core feature

B. Environmental State Change Analysis
- Use fixed CCTV viewpoint
- Learn normal background/environment state
- Detect persistent state changes
- Distinguish temporary objects from accumulated pollution
- Use object count, density, duration, and temporal accumulation for pollution scoring

C. OCR-Based Visual Sensorization
- Place a low-cost digital thermometer/hygrometer inside CCTV view
- Define fixed ROI coordinates
- Apply OCR only to that ROI
- Extract temperature and humidity values
- No object detection is required for this feature because CCTV angle and sensor position are fixed
- This provides low-cost local micro-environment data that weather APIs cannot provide accurately

D. Pollution Score Calculation
Use:
- detected object count
- object area or density
- persistence duration
- accumulation over time
- OCR-extracted temperature/humidity data

Output:
A quantified pollution score for each monitored area.

E. Central Server
- Receive results from Raspberry Pi
- Store data in database
- Provide REST API and/or WebSocket
- Manage events and notifications
- Serve dashboard data

F. User Dashboard
- GIS map
- CCTV-specific pollution status
- time-series charts
- event alerts
- event images or snapshots
- environmental reports

Future Extensions:
Keep these separate from MVP:
- fire detection
- smoke detection
- hazard detection
- additional OCR-based instrument reading
- multi-CCTV integrated monitoring
- Coral USB Accelerator support
- Jetson device support
